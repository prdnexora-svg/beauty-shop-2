## Remaining gaps (backend-dependent, unchanged from the audits)

These cannot be completed from source alone — they need a live Supabase project, deployment access, or product/legal sign-off:

1. **Live auth & RLS verification** — `0004` SECURITY DEFINER privileges, trust-field write protection, and public profile projections need inspection of the *deployed* database, plus `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` configuration.
2. **Shared backend CRUD** — RFQs/quotes/messages/products flow through the local relational store with Supabase sync scaffolding (`syncAllDataToSupabase`); true cross-device delivery needs the configured backend. The UI is now fully wired against the repository layer, so the swap is confined to `src/db`.
3. **Durable uploads** — document/image attachments use in-browser object URLs; private storage buckets with owner RLS remain backend work (UI file validation is in place).
4. **Supplier verification review states** — loaded from the portal flow locally; production review queues need the backend.
5. **Policy/support/social pages** — need approved legal content and official URLs before launch.
6. **Bundle size (P2)** — main chunk ~1.54 MB minified (~382 KB gzip); route-level code splitting is now straightforward since screens are addressable, but was intentionally not bundled into this fix pass.
7. **4.3 stored invoice files / 4.8 multi-currency** — remain partial by design (offline PDF/CSV is the accepted scope; currency is INR-only).
